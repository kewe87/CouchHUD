# CouchHUD – Guide (English)

The English guide. Overview and screenshots: [README](../README.md#english). The German [GUIDE.md](GUIDE.md) is the complete reference (configuration, architecture, every setting); this page covers the same features more briefly.

CouchHUD is a controller-first, full-screen interface for the living-room PC on your TV. It can replace the whole Windows shell (`explorer.exe`): after sign-in you land directly in CouchHUD, control everything with a gamepad, and only leave it when you choose to switch to **PC mode**. It is independent of Steam Big Picture, Playnite and friends, but it finds your Steam, Epic, GOG, Ubisoft and Xbox games automatically.

## Language

The interface comes in **English and German**. Out of the box CouchHUD follows the Windows display language (German for `de-*`, English for everything else). You can change it any time under *Settings › Info › Language*; the change applies immediately. The host messages (notifications, tray menu, installer) follow the same setting. Steam store descriptions are loaded in the interface language.

Translators and contributors: see [i18n.md](i18n.md) for where the texts live, the rules and the terminology table. `scripts/i18n-check.mjs` (part of `scripts/check.sh`) makes sure both languages have the same keys.

## What it does

**Look and feel**
- **Console-style UI** with Home, Games, Apps, News, Smart home (once Home Assistant is connected), Assistant (once an AI provider is set up) and Settings. 1080p to 4K.
- **Skins**: CouchHUD, PS4 Classic, Xbox, Cyberpunk, Nova, with live preview; your own skins are plain CSS ([SKINS.md](SKINS.md)).
- Clear logos, hero artwork and muted background trailers, colors taken from the artwork, parallax and tilt with a light reflex, a launch transition, HDR effects, UI sounds and optional background music per skin. *Settings › Look › Reduce animations* tones the movement down.
- **Screensaver** against OLED burn-in (artwork slideshow, moving clock, dim or black, pixel shift, optional display off).

**Library**
- Steam, Epic, GOG, Ubisoft Connect, Xbox / Game Pass, watched game folders and your own apps (EA app and Battle.net run as game clients; their games come in through watched folders or own entries).
- **Adding**: the last tile of the Games and Apps pages is **+ Add** (also in the filter menu, X). On the Apps page CouchHUD first offers the **list of installed programs** like the Start menu, Store apps such as Claude included (LB/RB jump letter by letter, X searches; "Other …" at the end picks a file). Entries already in the library are marked. Store apps are started by Windows itself (`shell:AppsFolder`); since no program folder is known, CouchHUD does not show them as "running". Adding needs the code while the couch is locked.
- **Startup parameters and working folder** (Expert mode, your own entries with an exe only): in the entry's edit dialog. The parameters go to the program one by one, without a shell; the working folder has to exist. The assistant and MCP cannot change them (only when creating an entry with `add_entry`, which asks on the TV). Example "Claude Code": program `C:\Users\<name>\.local\bin\claude.exe`, parameter `--continue`, working folder `D:\couchhud` (or `wt.exe` with `-d D:\couchhud claude --continue` for Windows Terminal). Terminals, shells and interpreters (`claude`, `python`, `node`, `bash` …) are never games, only apps; on a locked couch they need the code.
- Artwork from SteamGridDB (with your own key) and the Steam store. Local sources come first (Steam's `librarycache`, the Epic Launcher's catalog cache, Xbox package logos, the Ubisoft cache, program icons), then the Steam CDN and SteamGridDB; if nothing is found CouchHUD draws a banner itself. **Every image is downloaded once and then kept in the local artwork cache** (`%LOCALAPPDATA%\CouchHudrtwork`, about 750 MB at most, images of current entries are kept). The UI never loads artwork from the internet itself. Expert settings can turn online artwork off and clear the cache. **Change artwork** per entry from all matches or your own picture.
- **Collections** (for example "Couch co-op", "Kids"), pinned to Home if you like. Favorites, search, sort, filter, play time.
- **Save games**: back up and restore with the Ludusavi manifest (Windows files; registry saves are shown but not yet backed up).

**Controls**
- **Guide button** even over a running game: a tap brings CouchHUD to the front (the game keeps running, optionally frozen), holding it always brings you back from a game or PC mode. What a tap does is a setting (*Settings › Controller › Guide button in game*).
- **Guide menu**: back to the game, quit or force quit, volume (per app), audio output, CPU/GPU/RAM, weather, notifications, Bluetooth, captures, running programs, sleep timer, power.
- **Phone as keyboard and remote**: scan the QR code on the TV. The setup creates one inbound allow rule in the Windows firewall named **"CouchHUD Remote (CouchHUD)"** (TCP, only the ports in use, only the local subnet; Windows' own rules are not touched). The link is plain HTTP in your LAN, so the phone never types into password or key fields (CouchHUD checks the field before typing into another window; where Windows cannot tell and the window belongs to a launcher or browser, such as Steam, Epic, Chrome, Edge or CouchHUD's own browser, the phone does not type at all and asks you to use the TV, while games and other programs without an answer stay allowed), only devices of your own network are accepted (private and link-local addresses; 100.64.0.0/10, i.e. Tailscale and other CGNAT networks, are deliberately refused), and paired phones can be unpaired one by one and expire after 180 days of no use. **On-screen keyboard**, **file browser**, **TV browser**, and the controller can act as a mouse for logins and dialogs. The TV browser is part of the CouchHUD window (not a window of its own) with a slim bar on top: back, forward, reload, address (tap it for the on-screen keyboard), zoom, start page, close. The bar hides after a few seconds and the View button brings it back; B goes back in the history and closes at the start, LB/RB zoom, Guide leads to CouchHUD, videos play full screen. **Every link in CouchHUD opens here** (news, plugins, website entries), never in Windows' default browser; the couch lock rules apply (locked, CouchHUD asks for the code), and only http and https open. After closing you are back where you came from (e.g. the article). **Exception, streaming with copy protection:** Netflix, Disney+, Prime Video and the like do not play in the built-in browser (WebView2 ships without Widevine); those website entries have "Open in Edge" (the entry's edit menu), preset for known services. Only it uses the setting "Open Edge full screen". Known limit: Google blocks sign-ins in embedded browsers.
- **Wi-Fi**, **Bluetooth**, **display** (resolution, refresh rate, HDR, night mode), **game profiles**, **per-app volume**, **Windows and app updates**.
- **News reader**, **Home Assistant**, **weather**, **AI assistant** (your own API key) and an optional **MCP server**.
- **CaseHUD** (Settings › CaseHUD): control the LCDs in your fans and pumps from the couch. CouchHUD can install [CaseHUD](https://github.com/kewe87/CaseHUD) for you (verified download, one UAC prompt), starts it and talks to its local API: live display tiles, design grid per display, brightness, rotation, mode, one set for all displays, scenes, community designs, AWTRIX, and "Open on the PC" for the design editor. The Guide menu has displays off/on and next scene. CaseHUD stays a separate program; CouchHUD contains none of its code. It installs and updates only from signed releases; if the downloads are not reachable right now the page says "Downloads not available right now" and *Check again* asks by hand. **CaseHUD interface:** CaseHUD ships with its API switched off. While it is off, the CaseHUD page, lighting, the Guide menu, the setup assistant and "What CouchHUD changes" show the hint *Turn on the API in CaseHUD under Settings → Interfaces*; *Turn on the interface* does it after asking (couch unlocked), *Open on the PC* shows the switch in the CaseHUD window. With full integration CouchHUD offers on the install page and in the assistant to turn the interface on for your account right after installing (expert setting *Turn on the interface after installing*); the page of the running CaseHUD can turn it off again. Details: [CASEHUD.md](CASEHUD.md) (German).
- **Plugins and skins** from the community (`.zip` or the signed catalog, with update hints); the Wand plugin (formerly WeMod) is included. The default catalog [`kewe87/CouchHUD-Catalog`](https://github.com/kewe87/CouchHUD-Catalog) holds real entries (Wand, Synthwave) with a signed index and checksums.

**Console mode**
- **Runs without administrator rights.** What needs admin (lock policies, pausing gaming services, automatic sign-in, Windows Update, firewall, updates) is done by the Windows service **CouchHud.Service** from a fixed list of operations, with no UAC prompt day to day. CouchHud.exe never starts itself with administrator rights. What a parent or an administrator must approve, CouchHUD asks for with the parents' code or, as the fallback, Windows' User Account Control (see [CouchHUD service, codes and grants](#couchhud-service-codes-and-grants)).
- **Standard account for kids**: no administrator token is needed day to day. The service only ever works for the account that calls it, so a normal standard account can set the lock policies without an administrator dialog; releasing them takes an approval (code or Windows sign-in) or an administrator. If children use the controller, set CouchHUD up for such a standard account (details and limits under *Background service* below).
- **Two integration levels**: *Light* (default, the beginner mode) is a normal full-screen app: Steam & co. stay as they are and CouchHUD does not step in (no starting, no closing, no moving windows away, no Steam settings). *Full* starts the clients with it (Steam & co. run quietly in the background and are closed on quit) and replaces the Windows shell (CouchHUD runs as the shell **without Windows Explorer**; the desktop only comes back in PC mode or after emergency mode) and takes over autostart, sign-in and services. *Settings › Console › Set up CouchHUD as a console* walks you through it in one go (with an overview before and a result list after); *Back to normal Windows* undoes everything. Every change is listed on the transparency page ("What CouchHUD changes in Windows") with its way back.
- **CouchHUD stays in front**: a foreground guard keeps game clients (Steam, Epic, EA, Ubisoft, GOG, Battle.net, Xbox app, Playnite) and update pop-ups from covering the couch UI, and the Windows Game Bar hands over the Guide button. Steam stays out of the way too: it does not start in Big Picture mode, its Guide button does not focus Steam, no Big Picture overlay when a controller is used, no pop-up when a controller connects (Steam's own settings, nothing on your account; the Steam overlay and Steam's Guide shortcuts in games stay). Steam writes its files itself, so CouchHUD only changes them while Steam is not running: if it runs, CouchHUD ends it only to apply and only at a quiet moment (no game, no Steam window in front, no download, no sign-in) cleanly, writes the values and starts it again quietly; otherwise it waits. Putting back never restarts Steam, it happens as soon as Steam is not running. All of it is undone in PC mode, in Light mode and on quit (for Steam only what is still CouchHUD's: if Steam or you changed something since, it stays).
- **Game clients in the background** (full integration only; in Light mode CouchHUD does not step in): Steam, Epic, GOG Galaxy, Ubisoft Connect, EA app and Battle.net each have a mode (*Settings › Game clients*): *Standby* (default: starts quietly with couch mode so updates and downloads run right away), *On demand* (starts with the first game or action that needs it) or *Off*. When CouchHUD quits and when PC mode starts, it closes the Steam it started itself (with `-shutdown`, never by force); a Steam that ran before or that you started (again) yourself is left alone. If Steam is downloading or a game runs, it stays open (with a notice in PC mode). The other clients are left open for now: there is no download detection for them and no proof that closing cannot cut something off. Steam's couch settings are written before CouchHUD starts it and put back after CouchHUD ended it; only a Steam that ran before CouchHUD is restarted briefly for that, at a quiet moment.
- **Couch lock** and **PC mode**: leaving CouchHUD takes a controller code (six to eight buttons) or your Windows sign-in; a guard process locks Windows if CouchHUD quits or crashes. While the lock is closed, CouchHUD launches only games (apps and websites need the unlock), keeps game clients down even during a game, minimizes clearly recognised non-games (settings, Explorer, consoles, browsers outside the game), closes file and print dialogs and sets reversible Windows policies (no Control Panel, no Run box, no command prompt, accessibility shortcuts off; cmd, PowerShell, regedit, mmc and wt cannot be started through the Windows shell while locked). The unlock is short and **now also ends with every game start and every return to the HUD, no longer only with parental controls on**; in the browser it is extended while in use, and the browser closes as soon as the couch is locked again. The Windows sign-in as the lock needs an account with a password. The controller code also works without one, CouchHUD then warns clearly; automatic sign-in is left out without a password (Windows signs in anyway). To be honest: **the lock is only as strong as the Windows password of the account.** It keeps kids and guests at the controller out, not someone with a keyboard, boot media or a removed drive, so **device encryption / BitLocker is recommended** (the one-button setup points it out but does not turn it on). Pair it with the automatic sign-in that the one-button setup creates (Windows stores the password as an LSA secret; CouchHUD never keeps it).
- **Parental controls** (*Settings › Parental controls*): daily play time (weekdays and weekend), time windows, per-game limits, locked games, age limit (USK 6/12/16/18), warnings 15 and 5 minutes before the end, extension only with the parent code. They work only as the shell with the couch lock on, and they protect against children at the controller, not against someone with file access to the user profile; games that were not started through CouchHUD are counted while CouchHUD sees them running.
- **Emergency mode (emergency brake)**: hold Ctrl + Shift (or LB + RB + View) for about 1.5 seconds during start-up, or crash three times in a row within a few hours. Anyone at the controller can trigger it, so it works in two steps: CouchHUD first only locks Windows and waits. **Only after you sign in with the account password** it removes the shell entry and an automatic sign-in that CouchHUD set up, and the normal desktop comes back. Choosing "Restart" at the lock screen leads back into the couch. Without a couch lock the first step is skipped. If Windows cannot be locked for the first step, even after several tries, CouchHUD changes nothing, counts the unclean ends again (the next start tries once more), shows a message and starts the couch as usual behind its lock: a child at the controller must not reach the desktop without the password. If an automatic sign-in stays (set up with netplwiz, say) and CouchHUD is not the shell, a Run entry of the account locks Windows right after an **automatic** sign-in (recognized by the session being signed in within a few seconds); a manual sign-in is not locked again. The entry follows every change of shell, automatic sign-in and couch lock and goes with the uninstall.

  **Broken settings file**: if `config.json` is damaged or unreadable, CouchHUD runs locked (Windows sign-in as the couch lock, parental controls strict: no game starts) and writes nothing to the file until it is usable again. Unreadable (held by another program): tried again every 15 seconds. Damaged: **the way out is to repair or delete `config.json`** (CouchHUD then starts with defaults; lock and parental controls are off afterwards). The `config.json.<time>.bad` next to it is only a copy (same content only once, at most five). The few emergency fields (the "shell removed" notice, returning to the couch) are kept in `config.json.recovery` meanwhile and merged back after the repair.

  **Background service**: the setup installs the Windows service CouchHud.Service (LocalSystem, in `C:\Program Files\CouchHud\service`). It offers a fixed list of operations with checked parameters, never "run this program" or "open this path", and the account is always the caller's own. Gaming services are paused only from its own fixed list, and resumed only if it paused them. The service replaces the scheduled tasks of earlier versions; only the reserve task "autologon off" stays for the recovery. If the service is missing, the couch lock stays closed (fail-closed); "Repair service" sets it up again (see *Emergency exit*).

  **Approved plugins**: the list of approved plugins (`plugin-trust.json`) is signed with an HMAC (same key as `playtime.json`, bound to the Windows account with DPAPI). It protects against a program or script that merely writes files, not against a program running as the same account (it can read the key too). If the signature does not fit, the plugins show an error, nothing unknown loads and the file is not overwritten; delete it to start over (what lies in the plugin folder then counts as approved at the next start, as on the very first start).

## Install

Windows 10/11 and an XInput controller (Xbox pad, or PlayStation pads via Steam Input / DS4Windows). Download `CouchHud-Setup-<version>.exe` from [Releases](https://github.com/kewe87/CouchHUD/releases). The setup is available in English and German and installs to `C:\Program Files\CouchHud`; it is not Authenticode-signed yet, so SmartScreen warns on first start. CouchHUD updates itself from GitHub releases (it installs only after verifying a signed checksum file and the setup's SHA-256).

**First start:** a setup assistant asks a few questions, one per screen: language, confirming the disclaimer and privacy notice, *Light* or *Full*, skin with live preview and mouse pointer, sound, and with *Full* the game clients (*Keep ready* or *On demand*). Choosing *Full* only records it: *Let’s go* on the summary then starts the console setup from *Settings › Console* (administrator approval, controller code, restart offer); if it stays incomplete, CouchHUD says so briefly. While the assistant and the first-start notice are open, no notification cards appear, only the bell counts. Y skips a step, ≡ ends the assistant; everything stays changeable in Settings, and the assistant sets nothing that is not there. Run it again under *Settings › Info › Run setup assistant again* (with the couch lock on, only after the code). Installs from before the assistant are offered it once, never forced into it.

## Controls

| Controller | Keyboard | Action |
|---|---|---|
| D-pad / left stick | Arrow keys | Navigate |
| A | Enter / Space | Select |
| B | Esc / Backspace | Back |
| X | X | Context action (in Games and Apps: search, sort, filter, collections) |
| Y | F / Y | Home and details: favorite. Games and Apps: tile menu (favorite, collections …, details). Smart home: pin to the Guide menu |
| LB / RB | Q / E or Page Up / Page Down | Switch tab |
| Start | M | Power menu |
| Guide (middle button) | Home | Guide menu. A tap over a game brings CouchHUD forward (setting); **hold** always returns from a game or PC mode |
| Back + Start | – | Alternative to the Guide button |
| LB + RB + View at start-up (~1.5 s) | Ctrl + Shift at start-up (~1.5 s) | Emergency mode: normal desktop instead of CouchHUD |

On-screen keyboard: A types, X deletes, Y space, LB shift, RB symbols, Start done, B cancel. With a real keyboard you type straight into the field (Enter finishes, Esc cancels). When you drive the keyboard with arrow keys, Enter presses the marked key and **Ctrl + Enter** finishes.

### Controller gone?

Battery empty, Bluetooth switched off by accident or the receiver unplugged: CouchHUD always works with **keyboard** and **mouse** (or touch) too, including the couch lock's code prompt and the parents' code.

- **Code without a controller:** below the dots of the code prompt are the ten code buttons (A, B, X, Y, LB, RB, ↑ ↓ ← →) to click. On the keyboard: **Enter = A, Esc or Backspace = B, X, Y, Q = LB, E = RB, arrow keys = D-pad**; **M** cancels (in the code prompt Esc is the B button, not "cancel"). It is the same code, checked by the CouchHUD service the same way with the same count of wrong tries (after 5 wrong ones every further try waits longer). With no controller connected the prompt says so and shows where Bluetooth stands.
- **Bluetooth comes back on:** while a Bluetooth controller is paired and no other controller is connected, CouchHUD switches Bluetooth back on at start (so also after a restart of the PC) and whenever it goes off. If keyboard or mouse were just in use, a 10-second countdown comes first with *Switch on now* and *Leave Bluetooth off*; B or a click next to it only hides it. While a code prompt or the time-up page is on screen, the countdown does not cover it (only a hint) and shows up afterwards. *Leave off* lasts until Bluetooth is on again or CouchHUD starts again. In **airplane mode** (every radio off) the same holds at start too: with keyboard or mouse the countdown comes first; without any other input CouchHUD still switches Bluetooth on so nobody is locked out. CouchHUD only switches the existing radio on: it never pairs new devices and never makes the PC discoverable. A radio disabled in Device Manager, by policy or a hardware switch, or a missing adapter, is only logged. If switching on fails, CouchHUD retries with growing gaps (30 s up to 15 min) and stops after 6 failures until the next start; at most 3 times in 10 minutes. If something else keeps switching Bluetooth off, CouchHUD stops after two full 10-minute windows until the next start. To turn it off: *Settings › Controller › Switch Bluetooth on automatically for controllers* (expert mode, needs the code with the couch lock on).
- **Switching Bluetooth off in CouchHUD:** if your controller is connected over Bluetooth, CouchHUD asks first. With another controller connected or keyboard or mouse just in use, Bluetooth then stays off (like *Leave Bluetooth off*); otherwise it comes back by itself after a short while.
- **When nothing works any more:** press `Ctrl + Alt + Del`, then **Sign out** or **Restart** (bottom right). After the restart CouchHUD switches Bluetooth back on by itself (see above), and the controller reconnects once you switch it on with its guide button.

## Emergency exit

Hold Ctrl + Shift (or LB + RB + View) for about 1.5 seconds during start-up, or crash three times in a row: Windows locks, and **after you sign in with the Windows password of the account** you get the normal desktop and CouchHUD stays out of the way until you start it yourself. That password is the account's, which the owner knows, not the couch code. An account without a password needs just a click at the lock screen, which is why parental controls require a password. Otherwise: Ctrl + Alt + Del › Task Manager › Run new task › `explorer.exe`.

**Repair service**: if the CouchHUD service no longer runs, "Repair service" sets it up again with its fixed, hardened configuration (Windows programs only: `sc.exe`, `icacls.exe`, `reg.exe`). Before you confirm the UAC prompt, open *Show more details*: the program must be `C:\Windows\System32\cmd.exe` with the command line `/d /c ""C:\Program Files\CouchHud\repair-service.cmd""`. If it shows anything else, cancel.

### CouchHUD service, codes and grants

Everything that needs administrator rights is done by the **CouchHUD service** (`CouchHud.Service`, runs as SYSTEM, lives in `C:\Program Files\CouchHud\service`). CouchHUD itself never runs with administrator rights and talks to the service only over a local pipe; before every contact it checks that the pipe really belongs to the service. The service only ever acts for the account that calls it (taken from its Windows sign-in, never from the request), and only from a fixed list of actions.

- **Codes and the lock mode live in the service.** The service checks the couch code and (with parental controls) the parents' code itself, with its own count of failed attempts per code: after five wrong codes every further attempt has to wait, 30 seconds first, then twice as long each time, at most 15 minutes. The count survives restarts of the service and the PC. The service also knows the account's lock mode (off, Windows sign-in, code): switching it on or making it stricter is always possible, weakening or switching it off only with the proof of the current mode (code or unlock) or a parent or an administrator. The first code is free only while no lock is on, and survives a lock being switched on only when it is set in that step (CouchHUD asks for the code when the code lock is switched on); the code mode without a code stays closed. Switching off also removes the code from the service, and so does switching to the Windows sign-in (there only the unlock counts; CouchHUD says so before the switch). Going back to the code, you set a new code right away and confirm it once with the Windows sign-in (with parental controls, with the parents’ code), no administrator needed; "parental controls off" removes the parents' code. The configuration in the user folder no longer holds a code hash. The service's data (`service\data`) can only be read by SYSTEM and administrators. *Settings › Console* shows which codes the service holds for this account.
- **Update from 0.4.0 with the couch lock on:** the lock stays on. The first time it is opened after the update, an administrator confirms it once through the Windows prompt (UAC; program `sc.exe`). CouchHUD says first what is confirmed and why: for the code lock "the code just entered", which then is the lock's only code; for the Windows sign-in the "Windows mode". Reason: in 0.4.0 codes were kept in a file any program of the account could change. Every other code the account had, a parents' code too, no longer counts afterwards; a parents' code is set again in the settings. If the code entered does not match the stored one (or none is stored), CouchHUD first asks whether an administrator should confirm it as the new code; UAC only comes after "Confirm as administrator". If the lock was confirmed with the old 0.4.0 code, CouchHUD reminds you that this code lay readable in the configuration: set a new code in the settings afterwards. Until then neither the code nor the Windows sign-in nor a parents' code releases the lock, only an administrator; the lock mode can only be changed that way until then, single codes not at all. Afterwards the code opens it as usual.
- **Grants.** A right couch code gives a grant for 2 minutes (the unlock window), bound to the account, the Windows sign-in and the Windows session. It ends earlier when the session is locked, disconnected or signed out, and does not count while the session is locked. With it the service releases the lock policies, opens the firewall rule, or keeps the session during an update. In the "Windows sign-in" lock mode the unlock of the caller's own session counts instead, as seen by the service itself; never in the code mode, never for an account without a password, and never a mere sign-in.
- **What a parent or an administrator must approve**: the automatic sign-in, changing or removing the parents' code, changing or removing the couch code next to a parents' code, weakening the lock while there is a parents' code, opening a lock that has no code. CouchHUD asks for the **parents' code**; the grant then counts only for exactly that action, once, for 30 seconds. If that does not work (no parents' code, too many wrong attempts), an **administrator** of this PC approves through Windows' **User Account Control (UAC)**: CouchHUD first says what is being approved; then Windows' own UAC prompt on the secure desktop shows the program `sc.exe` (service control) with `control CouchHud <number>`. The administrator's password is typed only into that Windows prompt; CouchHUD never sees it. The grant goes to the account at the couch, not to the administrator, only for the named action, once; the request expires after 60 seconds. When a parent or an administrator sets a single code anew, the other kind goes (a planted code does not survive that); with parental controls CouchHUD always sets both.
- **Parents' code.** With parental controls the parents' code is the couch code. The service takes it only together with a new code (both in one step) or with the approval of a parent or an administrator; the couch code alone never makes a parents' code. So when parental controls are switched on at an unlocked couch, CouchHUD asks for the code right away and saves it as couch and parents' code; an administrator approves that once through UAC. When they are switched on at a locked couch, CouchHUD deliberately sets no code (a locked couch takes no new code); then set the code again at the unlocked couch.
- **Takeover on update.** On first contact the service takes over the code hash and the lock mode from the configuration, once per account. **Honest limit:** at that moment the service cannot know whether a program of the user changed the configuration before. It only accepts a hash in CouchHUD's format, never over a code it already knows, and a mode never weaker than the one it already knows; from then on it is the authoritative source. If the service holds codes the settings do not know, the setup assistant says so.

**Honest limits of the service**
- An administrator's password never passes through CouchHUD: Windows' UAC prompt takes it. **Honest limit:** the prompt shows only `sc.exe control CouchHud <number>`, not the action. Only one request is open per session; a program that already runs as your account could still place its own before CouchHUD does (another action, same account), and an approval binds the action, not its details. So only approve when you just started the action yourself and CouchHUD just announced it. The automatic sign-in password and the code buttons, however, arrive as .NET strings, which cannot be wiped and stay in memory until the garbage collector removes them. None of it is logged.
- The **Windows sign-in** still opens the way when the service is not running (emergency exit above): whoever knows the account's Windows password gets to the desktop. A sign-in gives no grant in the service, though: what a crashed run left restricted, the service releases afterwards only with the code, an unlock in the Windows mode, or an administrator (UAC).
- A program that already runs as your account can read the controller and take grants from CouchHUD's memory. The service raises the bar against children at the controller and against the UAC boundary, not against malware in your own account.
- The "account without a password" check shows up once per account and service start as a failed sign-in in the security log.
- **"Repair service"** asks for an administrator through UAC and only starts `cmd.exe` with the fixed repair script from the program folder (see above, check the details in the UAC prompt).
