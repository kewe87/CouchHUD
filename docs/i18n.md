# Languages and terminology

CouchHUD speaks German (default for German Windows) and English. The language is a setting
(`Language`: `auto`, `de`, `en`); `auto` follows the Windows display language: `de-*` gives German,
everything else English. Settings, Simple mode, Info (or Display) has the switch; it takes effect
right away.

## Where the texts live

| Part | Files | Access |
|---|---|---|
| UI (WebView) | `ui/i18n/de/*.js`, `ui/i18n/en/*.js` (one file per area, same file names in both) | `t('area.key', { name })` from `ui/core/i18n.js` |
| UI, static HTML | `data-i18n`, `data-i18n-title`, `data-i18n-aria` attributes in `ui/index.html` | applied at start |
| Host (C#) | `src/CouchHud.Core/Localization/Strings*.cs` | `Strings.Get("key", args)` |
| Installer | `[CustomMessages]` in `installer/CouchHud.iss` (de, en) | `{cm:Key}` |

Rules:

* Every key exists in German and English (`scripts/i18n-check.mjs` and the Core test check this).
* Placeholders are `{name}` in the UI and `{0}` in C#; both languages use the same ones.
* Plurals: a value `{ one: '…', other: '…' }` and `t(key, { count })`.
* `t()` is called when the text is built, never in a top-level constant (the language can change).
* Dates, times, numbers: `fmtDate`, `fmtTime`, `fmtNumber` from `i18n.js` (never a hard-coded locale).
* Keys that are built dynamically are listed in a `// i18n-used: area.a area.b` comment so the check knows them.
* Names that are brands or product features stay as they are: Steam, Epic, Xbox, Guide button, CouchHUD.
* Paths through the settings use `›` ("Settings › Library"), never `→`. Quotes are typographic (“…” in English, „…“ in German), never straight.

## Host states and stored texts

Whatever the UI compares or shows later must not be a finished sentence from the host:

* **States the UI reacts to** (an error that changes what is shown) come as a **code** next to the text, e.g. the self-update check sends `errorCode` (`noRelease`, `rateLimit`, `noAnswer`, `unreachable`) and the catalog sends `errorCode` (`notFound`, `unreachable`). The UI translates the code (`updates.self.err.*`, `plugins.catalog.*`) and never compares texts.
* **Notifications** keep a key and arguments, not the text: `Strings.Ref("hud.played", …)` / `Strings.RefPlural(…)` when posting, `Strings.Render(text)` when they are handed to the UI. They read in the language of the moment, also after a language switch.
* **Store texts** (Steam description) are fetched and cached per language (`l=german` / `l=english`).
* **Plugins** get `IPluginContext.Language` and `Events.LanguageChanged` (docs/PLUGINS.md, "Zwei Sprachen"); `plugin.json` and the catalog give `description` per language.

## Style (English)

Console style like Xbox or PlayStation: short, direct, no full stops on labels, title case only for
page titles, sentence case for everything else. Say what the button does ("Launch", "Back up saves").
No literal translations; no technical terms in Simple mode.
